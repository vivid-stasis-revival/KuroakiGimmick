# Custom 图片合成与循环编辑修复

针对 Cutie Mew Mew Magic 的图片错位、低图片层级下轨道演出异常，修正了 Custom 对象的场景采样边界。

原实现把低于 -200 的图片直接画在 scene，其它图片分段画入透明 field 再进行 Proxy 变换。它使低层级图片留在原位，并导致从背景、侧边或整幅场景取图的 Proxy 丢失内容。修复后先按深度合成完整源画面，再复制一次供所有 Proxy 裁剪、变换；目的画面先清黑，避免未变换的原图残留。预览和视频导出共用此路径。无 Proxy 事件的场景和原生对象保留原路径。

另外按原始矩阵代码修正 Custom Proxy 的旋转方向，以及 shxa 改变原始左边界时的横向锚点。图片本地姿态计算保持原样。

依据本机源码：CustomGimmick `gml_Object_obj_custom_gimmick_Draw_74.gml` 捕获完整 `application_surface`；`gml_Object_o_csm_sprite_drawer_Draw_0.gml` 绘制普通场景图片；VS `gml_Object_obj_base_gimmick_Create_0.gml` 的 MToOrigin 为 (-47,-82)，`gml_GlobalScript_Matrices.gml` 的 MatrixRotateZ 在 M[1] 使用正 sin。未将外部游戏源码或曲包加入仓库。

时间轴新增右键菜单：

- **SPLIT LOOP**：原位展开选中的循环，每次触发成为独立片段，首条保留原身份。
- **MERGE INTO LOOP**：把源文件中相邻、相同参数且等间隔的选中事件或循环合成一条括号循环。拒绝跨越其它事件，避免改变相同时间的执行顺序。
- 两种操作均通过文档事务提交，可一步撤销／重做。动态值、未改动字段、注释和 MPF 段保留。拆开一次最多一百万次触发；合并后上限同运行时。

验证包含负数／小数拍、两种循环语法、末尾无换行、已有循环合并、生产解析器事件等价、非法合并原子拒绝、BOM／CRLF 撤销与事件身份重做。Metal 像素回归覆盖十个图片优先级、原位残影、侧边图片裁剪、hom 隐藏原图、旋转、低层图片下的轨道移动和重新求值。Windows 原生运行及原曲截图时间点需要对应环境和曲包另行验证。

2026-09-19 验证结果：Release 构建 0 警告／0 错误；基础 292 项、编辑器 694 项、布局／图片 283 项、图片对象 123 项、创作／导出 48 项通过，共 1440 项 CPU／IO 检查。`--gpu-test` 在本机 Metal 通过，包括新增的 25 项 Custom Proxy 像素检查及已有渲染回归。

## 2026-09-20 原曲复现与透视补充（验收未完成）

用户提供的当前曲包有 24,094 条事件、268 张图片实例／84 个纹理、32 个 Proxy。报告中的 `prtrX`、`prtrY` 各 10 条未支持事件是实际缺项：它们在第 357 拍应用于 4–13 号 Proxy。已增加与 `MatrixTrapezoidal` 对应的齐次顶点变换，顺序为移至原点、缩放、旋转、透视、斜切、平移。保留 W 到光栅化，确保透视 UV 插值和跨投影平面的裁剪正确；不是在 CPU 除完四个角后画普通四边形。

另修正 Custom Proxy 缩放绝对值大于 50 时被丢弃的问题。原曲 31 号 Proxy 以 1000 倍缩放采样空白区域作为背景，忽略它会让固定侧边的原图残留。新增测试验证高倍率图像及背景遮罩仍可绘制。

原曲第 337.66 与 364.78 拍均已实际渲染，并通过逐个关闭 Proxy 定位：中央黑块来自 0、1 号 Proxy。恢复 31 号背景后外围原图消失，但这两个局部遮罩仍覆盖中央轨道，侧面构图也尚未与用户参考图一致。不能把移除两个 Unsupported 提示当作该曲验收通过。需继续核对参考画面对应的实际游戏／CustomGimmick 版本和运行时绘制行为；未改写用户曲包的任何参数。

本次 GPU 测试增加六组投影逆映射像素核对（包括投影平面穿越）、HLSL 顶点转译、VSM 参数接入、反向裁剪端点、1000 倍缩放以及透视／非透视之间切换。报告剩余九项是曲包中以 `!` 开头的 mod 名，保持原样，不自动当成去掉 `!` 的有效指令。

原曲截图和完整报告保存在被 Git 忽略的 `dist/validation/cutie-ftv-20260920/`。`current-*` 是当前待验收结果，保留中央遮挡问题，不能作为最终正确画面的基线。

### 第 389.65 拍的原生引擎对照

新增一次隔离实验：从当前会话取得未变换的完整场景与 32 个 Proxy 的求值结果，在独立小型 GameMaker 数据文件中使用本机 ExCustomVivid 17 的矩阵／Draw_74 绘制步骤及原版 shader_00_sine，再用本机 GameMaker 2024.0 runner 绘制。未运行原游戏的存档或歌曲逻辑，未改动原游戏和曲包。测试应用使用独立标识 local.codex.cutie-probe。

相同输入下，原生引擎也出现中央遮挡及窄侧面的相同几何形状。这是对绘制链的对照，并不验证 Timeline 提供的参数是否与实际游戏播放一致，也不证明手头模组代码与参考画面所用版本相同。两张图仍有采样／颜色差异，不能宣称逐像素一致。

同时对比了曲包 `FINALE.vmv` 缓存与 `Finale.vsm`：两者均为 24,094 条事件，按源顺序比较 beat、duration、From、To、mod 名与 Proxy，差异为零；没有证据表明这里是拿到了不同的事件文件。缓存的 easing 是运行时脚本 ID，未据此推断当前游戏的缓动函数映射。

该拍 0、1 号 Proxy 的 shader 可见裁片对应的目标矩形约为 `(41.00,13.07)–(129.93,73.10)`、`(157.72,13.07)–(246.65,73.10)`；这解释了为何中央上方被遮掉。不能凭参考图给其中一份副本添加特殊偏移，需要进一步核对真实游戏的逐 Proxy 参数和实际 CustomGimmick 版本。

### 指定源码核对与独立布局修正版

随后按用户提供的 `vs6201/CodeEntries` 与 `Downloads/cross/osx-arm64/mods/ExCustomVivid` 核对了初始化、矩阵、Draw_74、updateMod 补丁及 cc 的 tween 更新。又根据该模组日志找到本机实际安装的 game.ios，只读提取了相应已打补丁的代码和 shader。关键绘制公式与前述重放一致。对该曲 Proxy 控制事件按原版“每帧依次更新活动 tween，完成后移除”的规则独立模拟，389.65 拍的全部已检查参数与 Timeline 相同。

还将相同场景、参数和原始 HLSL 字节码交给 Windows GameMaker 2024.14 runner（通过 CrossOver 的内置 Direct3D 翻译路径）重放，中央遮挡同样存在。这不是 Windows 上运行本编辑器的验收，也不应被表述成正式游戏全过程的逐像素对照。

据此，剩下的布局问题以**独立 VSM 副本**交付，不往渲染器加入曲名判断或自动偏移。目录为 `dist/CutieMewMewMagic-layout-fix-20260920/`：
