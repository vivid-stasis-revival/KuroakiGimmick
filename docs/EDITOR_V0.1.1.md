# KuroakiGimmick v0.1.1 · Editor Preview 3

这是基于用户提供的 `KuroakiGimmick v0.1.0-15.3.zip` 修改的源码试用版，不是已验证的正式发布包。当前制作环境没有 .NET SDK，未完成 C# 编译、SDL_GPU 启动或 macOS/Windows 实机测试。静态检查与实际运行验证分开记录，见 `VALIDATION_V0.1.1.md`。

## 快速试用

需要 .NET 8 SDK。依赖沿用原工程，不引入新的 UI 框架。

macOS 在项目根目录运行：

```bash
bash scripts/run-editor.command
```

Windows PowerShell 在项目根目录运行：

```powershell
./scripts/run-editor.ps1
```

两个脚本都会先构建，构建失败立即停止，不会启动旧版本二进制。默认打开 `Samples/EditorDemo/demo.sgv.json`。

也可直接运行：

```bash
dotnet run --project KuroakiGimmick.csproj -c Release -- --editor Samples/EditorDemo/demo.sgv.json
```

第二个示例是 `Samples/EditorDemo/proxy.sgv.json`。现有 `scripts/publish-mac.sh`、`scripts/publish-win.sh` / `.ps1` 已更新版本标识。发布脚本不等于已经完成发布验证。

## Viewer / Editor

Viewer 原有页面和渲染路径保留。右上角增加 `EDITOR UI`；Editor 顶部有 `VIEWER UI`。Tab 切换工作区，不丢失正在编辑的内存文档。空工程需要先打开谱面或 VSM。

Viewer 左下方增加虚拟桌面与真实窗口入口，原先的主歌曲预览、检查与视频导出功能仍在 Viewer 中。Editor 不另建一套简化的歌曲渲染器。

Editor 分为添加面板、中央预览、事件属性、下方多轨时间轴。内部仍按 VSM 的 `proxy + mod` 或窗口事件的 `w + op` 分组，但左侧**只显示原始 mod/op 名**；GLOBAL / `P0` / `W0` 作为独立小标显示，不拼进名字。分组顺序只是界面组织，不会为整理视图而重排 VSM 源指令。

`scrollspeed`、`velocity`、`noterot`、`wave`、`notealp` 等常用 Note/SV 轨会固定存在，即使源 VSM 目前没有对应事件，也可以像剪辑软件的空轨一样直接点击 `+` 或双击添加第一段。存在 proxy 时还会预建 `prx/pry/prrz/przm/pra` 空轨。

## 推荐的第一次操作

打开 demo，暂停。点击上方四键音符参考轨的一颗音符。左边选 `prx`，点击 `+ GIMMICK CLIP`，新片段起点使用该音符的精确时间映射。点击片段后在右侧修改终值、持续时间或缓动。拖动片段主体移动，右侧手柄改变持续时间。播放或循环试听，再使用 Undo / Redo 对比。

双击某条轨道的空白处，或点击轨道名旁的 `+`，会在该轨添加相同种类的事件。`PRESET >` 当前只是常用参数模板切换，不是此前设计稿中的完整可复用组合预设系统。

拖动时显示片段位置预览，松开鼠标后提交一次历史记录并重建歌曲预览。没有把每个鼠标移动都记成一次撤销。

## 时间轴与输入

| 操作 | 行为 |
|---|---|
| 单击音符 | 选择精确时间参考，不修改 VSC |
| 拖动片段主体 | 保留语义持续时间，整体移动 |
| 拖动右侧手柄 | 修改事件持续时间；短瞬时事件可在属性里输入时长 |
| 双击轨道空白 | 添加本轨类型的事件 |
| 滚轮 | 上下滚动轨道；右侧属性区域内则滚动属性 |
| Shift + 滚轮 | 横向平移时间轴 |
| Ctrl/Cmd + 滚轮 | 围绕鼠标位置缩放时间轴 |
| Alt | 拖动时临时关闭吸附 |
| N MAGNET | 在屏幕距离 10 像素内优先吸附到音符 |
| 悬停轨道名 | 显示该原始 mod/op 的简短说明；持续按住 W 约 220ms 显示详细介绍 |
| SNAP | OFF、整拍、二/四/八/十六分拍，以及三连音相关网格 |
| A / B / L | 设置循环起点、终点、切换循环 |
| Space | 播放/暂停 |
| D / Delete | 复制选中事件到游标附近 / 删除选中事件 |
| Ctrl/Cmd + Z / Shift + Z | 撤销 / 重做 |
| Ctrl/Cmd + S / Shift + S | 保存编辑副本 / 另存为 |
| Escape | 取消拖动、关闭输入框或关闭真实窗口预览 |

数值输入框支持 `1/3`、`128+1/4` 和科学记数法；Enter 确认，Escape 取消，Ctrl/Cmd+A 全选，Ctrl/Cmd+V 粘贴。首版文本框为整体替换/末尾输入模式，不具备完整多行代码编辑器的光标操作。

音频轨是解码音频的峰值包络，不是事件密度。音符及 hold 尾部只作为时间参考。网格以 beat 标号显示，四拍较粗线仅是导航辅助，不声明已有完整拍号编辑。

### 两种持续时间不能混用

VSM 时间是拍单位，但沿用现有运行时的持续时间转换规则：使用事件起点 BPM 将 duration 转为秒。跨 BPM 的片段长度和拖动右端点已按该规则转换，不擅自改变原运行时语义。

WindowMovement 的 `t`、`easeDur`、`dur` 是秒；时间轴显示转换后的拍点。移动窗口事件保留秒持续时间，改变长度才写回秒持续时间。`_` 保持为 VSM 动态值，不会因为打开属性面板就替换成某个临时结果。

`start:end:step` 重复源行保持为一个片段，拖动修改整段源范围；不是选中某次实例单独修改。`mpf`、未知行、无法严格解析的行目前只保留，不提供可视化编辑。

## 保存规则

第一次 Save / Save As 请选择一个新的 `*.sgv.json` 文件名。保存生成三个伴随文件：

```text
my_edit.sgv.json
my_edit.editor.vsm
my_edit.editor_cgmk_config.json
```

原 VSC/VSB、原 VSM、图片、音频不会被覆盖。项目继续引用原素材，**不是自包含的歌曲资源包**。换机器时需要连同引用的歌曲文件一起保留相对路径，不能只拷贝这三个文件。

普通 VSM 以源行为基础保存，保留未修改字段的原始数字拼写、注释、未知行、BOM 与换行。内嵌于 VSB 的事件只会重建到新的 VSM 文件中，不回写二进制 VSB，也不宣称重建文本保留了不可见的二进制原始信息。

窗口配置保留无关 cgmk 设置及未知 JSON 字段，但 JSON 缩进可以变化。保存副本按事件秒时间排序，等时事件保持原相对顺序。旧 `ECG_WINDOW_MOVEMENT_FILE` 会解析为内联事件，保存内联副本。

本次会话中重复保存会检查输出文件哈希；外部修改后要求另存为。已有但不是本次会话创建的伴随文件不会被静默覆盖。因此，**重新打开已保存的工程后，首次保存仍需新文件名**。这是首版的保护性限制。

写盘前准备三个临时文件，保存备份及 journal，失败时尝试回滚。该操作不是跨多个文件的原子事务；进程意外退出时可依据 `.save-journal.json`、`.bak` 恢复。这里没有宣称具备完整版本管理或自动合并功能。

### 放回游戏

这三个伴随文件首先用于 Kuroaki 重新打开，不会自动安装到游戏。验证后，在歌曲的备份副本里将 `.editor.vsm` 的内容用作该难度的 VSM，将 `.editor_cgmk_config.json` 用作对应难度的 cgmk 配置，保留原资源引用；窗口功能还要求游戏端安装与配置匹配的 ExtCustomGimmick。首版没有一键部署、游戏安装修改或自动资源打包。

## 窗口编辑

参考 `WINDOW_MOVEMENT_V0.1.1.md`。窗口序号通过左侧 `WINDOW` 输入，支持 0..63 的预览范围，不写死四个窗口。选择事件后右侧可修改其字段；属性较多时使用滚轮或上下箭头。窗口 title/border 位于对应事件属性下部。

`SCENE` 切到 `DESKTOP` 是虚拟桌面，不会移动编辑器主窗口。`LIVE: OFF` 切到 ON 才创建真实 SDL 预览窗口。主画面 ID 0 也用辅助预览窗口表达，编辑器宿主保持原位。

## 本版边界

这是第一版事件剪辑器。已提供单选、单片段移动/长度调整、常用参数添加、属性输入、复制删除、撤销重做、音符吸附、试听循环和编辑副本保存。

尚未实现框选/多选、跨轨道拖拽改目标、同轨重叠片段展开、左端裁剪、磁性波纹剪辑、贝塞尔曲线编辑、参数化组合片段库、图片/VSP 资源创作、画布对象变换手柄、音符编辑、内置完整源码编辑器和剧情分支编辑。重叠事件可暂时通过源文件或属性移动处理，不宣称已有剪辑软件的完整交互。

Viewer 的 MP4 仍导出歌曲场景，不录制整个虚拟桌面或多个原生窗口。代理窗口目前只有普通模式的几何与内容预览；暂停、FCAC、结算合并、proxyMode00 和任意 GameMaker surface 来源还没有完整前端实现。原生特定演出的兼容性不会因为增加 Editor 就自动提高。
